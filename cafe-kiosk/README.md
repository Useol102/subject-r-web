# 카페 주문 키오스크 (1차 · 프런트엔드만)

교육용 카페 주문 키오스크 웹 1차 결과물이다. 화면 5개(시작 → 메뉴 선택 → 주문 확인 → 결제 방식 선택 → 주문 완료)를 **프런트엔드만으로** 구현했다.
실제 결제·데이터베이스·백엔드 연동은 없다. 메뉴는 `src/menu.ts` 상수이고, 결제는 2초 뒤 완료되는 흉내다.

> 이 폴더는 같은 저장소의 복지관 키오스크(`web/`, `web_api/`)와 **무관한 별도 앱**이다. 서로 코드를 공유하지 않는다.

## 실행

```powershell
Set-Location cafe-kiosk
npm install
npm run dev
```

`http://127.0.0.1:5174/` 를 연다. (복지관 화면 `5173` 과 겹치지 않게 포트를 다르게 뒀다.)

빌드·테스트:

```powershell
npm test          # 장바구니·금액 계산 · 진행 단계 테스트 (vitest)
npm run build     # tsc 타입 검사 + vite 빌드 → dist/
```

`dist/` 폴더째 옮겨서 `dist/index.html` 을 크롬 · 엣지로 더블클릭해 열면 된다. 설치 · 서버 · 인터넷이 필요 없다.
크롬은 파일로 연 페이지(file://)에서 모듈 스크립트를 막기 때문에, 빌드는 일반 스크립트(IIFE)로 만든다(`vite.config.ts`).

## 디자인 — "직관성 중심"

화이트 · 라이트그레이 바탕에 진한 글씨, 다음 행동은 파란 버튼 하나로 표시한다. 메뉴 선택부터 맨 위에 진행 단계(1 메뉴 선택 → 2 주문 확인 → 3 결제 방식 → 4 주문 완료)와 한 줄 안내가 나온다.
모든 단계에 "교육용 화면 · 실제 결제 없음" 을 표시한다.

- **글꼴**: 애플 기기는 시스템 글꼴, 윈도우 등은 함께 넣은 Pretendard Variable 1.3.9 (`src/assets/fonts/`, SIL Open Font License 1.1 — 원문 `OFL.txt`).
- **움직임**: 화면 · 팝업 전환 180~280ms, 버튼 눌림 반응. 운영체제의 "동작 줄이기" 설정이면 모두 끈다.
- **키보드**: 화면이 바뀌면 화면 제목으로 포커스가 간다. 팝업이 열리면 Tab 이 팝업 안에서만 돌고, Esc 로 옵션 · 결제 안내를 취소한다(시간 초과 창은 Esc = 시간 연장). 담은 금액이 바뀌면 화면 읽기 프로그램이 읽어 준다.
- 진행 단계와 안내 문구는 `src/flow.ts` (순수 함수, `flow.test.ts`), 팝업 키보드 처리는 `src/useDialogA11y.ts`.

## 메뉴 사진 넣기

지금은 사진 대신 단순한 그림(`src/screens/MenuArt.tsx`)을 그린다. 실제 운영 전에는 사진으로 바꾸는 것을 권한다.

1. `public/menu/` 폴더를 만들고 사진을 넣는다. 예: `public/menu/americano.jpg` (가로:세로 4:3 권장)
2. `src/menu.ts` 에서 해당 메뉴에 `photo: 'menu/americano.jpg'` 를 추가한다.
3. `npm run build` 를 다시 돌린다.

외부 인터넷 주소는 쓰지 않는다. 설치 후 인터넷 없이 돌아야 한다.

## 구조 원칙

- **금액·장바구니 계산은 `src/cart.ts` 의 순수 함수**에만 둔다. 화면 코드에 계산을 넣지 않는다. 바꾸면 `src/cart.test.ts` 를 같이 고친다.
- 메뉴 데이터는 `src/menu.ts`. 나중에 서버가 생기면 이 파일만 API 응답으로 바꾼다.
- 외부 CDN · 이미지 없음. 글꼴은 저장소에 함께 넣었다. 이모지도 쓰지 않는다(기기마다 모양이 다르고 장난스러워 보인다).
- 주요 버튼 52~76px, 주요 글씨 19~30px. 360 ~ 1366px 폭과 세로 키오스크(1080×1920)에서 가로 스크롤 없음을 확인했다.
