# 카페 주문 연습 (cafe-clean-ui)

고령층이 카페 키오스크 주문을 **미리 연습**해 보는 교육용 화면이다.
시작 → 메뉴 선택 → 주문 확인 → 결제 방식 선택 → 주문 완료, 다섯 화면으로 되어 있다.

- **실제 결제·서버·DB 가 없다.** 브라우저 안에서만 돌고, 새로고침하면 처음으로 돌아간다.
- **인터넷이 필요 없다.** 글꼴까지 폴더 안에 들어 있어 LAN 이 끊겨도 열린다.
- 모든 화면에 "교육용 화면 · 실제 결제 없음" 표시가 계속 떠 있다.
- 이 폴더는 같은 저장소의 Subject R 웹(`web/`, `web_api/`)과 **코드·데이터를 공유하지 않는 별도 결과물**이다.
  SubJectR 문구와 로봇 캐릭터도 쓰지 않는다.

---

## 1. 실행 방법

설치·빌드·서버가 필요 없다. **`index.html` 을 Chrome 또는 Edge 로 열면 된다.**

```powershell
start .\cafe-clean-ui\index.html
```

- `assets/` 폴더, `clean-ui.css`, `ui-enhancements.js` 를 `index.html` 과 **같은 위치에 그대로** 둬야 한다.
  하나라도 빠지면 화면이 깨지거나 하얗게 뜬다.
- 정적 파일뿐이라 GitHub Pages 나 아무 웹 서버 폴더에 올려도 그대로 돈다.

## 2. 사용한 언어·프레임워크·도구

| 구분 | 사용한 것 | 쓰인 곳 |
|---|---|---|
| 마크업 | **HTML5** | `index.html` — 실행 페이지, 상단 제목줄, 진행 단계 표시줄 |
| 스타일 | **CSS3** (CSS 변수, Grid, Flexbox, `@media`, `@keyframes`, `@font-face`, `clamp()`, `dvh` 단위) | `clean-ui.css` — 새 디자인 전체 |
| 스크립트 | **JavaScript (ES2015+, 바닐라)** — `MutationObserver`, 화살표 함수, 템플릿 문자열 | `ui-enhancements.js` — 진행 단계·안내 문구·키보드 포커스 보완 |
| UI 프레임워크 | **React 18.3.1** + **ReactDOM 18.3.1** (`createRoot`, `StrictMode`) | `assets/index-yXYbrbKE.js` — 주문 화면과 계산 로직 |
| React 기능 | 함수형 컴포넌트, JSX(자동 런타임 `react/jsx-runtime`), 훅 `useState` `useEffect` `useRef` `useCallback` | 같은 번들 |
| 빌드 도구 | **Vite** (추정) | 번들 이름이 `index-[해시].js` 형식이고, Vite 가 넣는 `modulepreload` 보조 코드가 들어 있다 |
| 원본 언어 | **TypeScript** (전달받은 설명 기준) | 원본 프로젝트는 받지 못했다. 빌드된 번들만으로는 TypeScript 여부를 확인할 수 없다 |
| 글꼴 | **Pretendard Variable 1.3.9** (woff2, 굵기 45~920 가변) | `assets/fonts/` — 윈도우·안드로이드용 |
| 글꼴 라이선스 | **SIL Open Font License 1.1** | `assets/fonts/OFL.txt` |

**쓰지 않은 것**

- 라우터, 상태 관리 라이브러리(Redux 등), UI 컴포넌트 라이브러리, CSS 프레임워크(Tailwind 등)는 없다.
  화면 전환과 장바구니는 React 기본 상태(`useState`)만으로 처리한다.
- 외부 CDN, 온라인 글꼴, 분석·추적 코드가 없다.
- `fetch`, `XMLHttpRequest`, `WebSocket`, `localStorage` 를 쓰는 앱 코드가 없다.
  번들 안의 `fetch` 한 곳은 Vite 의 모듈 미리 불러오기 보조 코드이고, 같은 폴더의 파일만 읽는다.

## 3. 폴더 구조

```text
cafe-clean-ui/
├─ index.html                  실행 페이지. 아래 파일을 순서대로 불러온다
├─ clean-ui.css                새 디자인 (색·글자·배치·반응형·모션)
├─ ui-enhancements.js          화면 보완 스크립트 (주문 상태는 건드리지 않는다)
├─ 제작-확인.txt               제작 범위와 검수 기록
├─ README.md                   이 문서
└─ assets/
   ├─ index-yXYbrbKE.js        React 앱 번들 (원본 그대로, 수정 안 함)
   ├─ index-DNhmxk91.css       원본 앱의 기본 스타일
   └─ fonts/
      ├─ PretendardVariable.woff2
      └─ OFL.txt               글꼴 라이선스 원문
```

**불러오는 순서** (`index.html`)

1. 글꼴 미리 불러오기 → `PretendardVariable.woff2`
2. 원본 기본 스타일 → `assets/index-DNhmxk91.css`
3. 새 디자인 → `clean-ui.css` (같은 클래스 이름을 덮어써서 모양만 바꾼다)
4. 앱 번들 → `assets/index-yXYbrbKE.js` (`<div id="root">` 에 화면을 그린다)
5. 보완 스크립트 → `ui-enhancements.js`

> 받은 zip 에는 쓰이지 않는 이전 빌드 번들 4개(JS 2개, CSS 2개)가 더 있었다.
> `index.html` 이 불러오지 않아 이 폴더에는 넣지 않았다.

## 4. 구조: 세 겹으로 되어 있다

원본 React 소스가 없어서 **원본 번들을 고치지 않고** 그 위에 두 겹을 얹는 방식으로 만들었다.

| 겹 | 파일 | 하는 일 | 바꾸면 안 되는 것 |
|---|---|---|---|
| ① 주문 로직 | `assets/index-yXYbrbKE.js` | 메뉴 데이터, 장바구니, 가격 계산, 화면 전환, 타이머 | 번들 자체. 축약된 코드라 손으로 고치면 깨진다 |
| ② 디자인 | `clean-ui.css` | 원본 클래스(`.btn-main`, `.product`, `.cart` 등)의 모양을 덮어쓴다 | 클래스 이름. 번들이 만드는 이름과 맞아야 한다 |
| ③ 보완 | `ui-enhancements.js` | 원본이 그린 화면을 지켜보다가 안내·포커스만 보탠다 | 주문 상태와 금액. 읽기만 한다 |

`ui-enhancements.js` 는 `MutationObserver` 로 `#root` 의 변화를 지켜본다.
원본이 `.kiosk` 요소에 붙이는 `data-screen` 값(`start` `menu` `confirm` `pay` `done`)을 보고 지금 화면을 안다.

## 5. 화면과 동작

### 화면 흐름

```text
시작 ─▶ 메뉴 선택 ─▶ 주문 확인 ─▶ 결제 방식 선택 ─▶ (결제 연출) ─▶ 주문 완료 ─▶ 시작
          ▲  "처음으로"는 어느 화면에서든 시작으로 돌아간다          │
          └────────────────── 20초 뒤 자동 복귀 ─────────────────────┘
```

| 화면 | 내용 |
|---|---|
| 시작 | "매장에서 먹고 가기" / "포장해서 가져가기" 중 고른다 |
| 메뉴 선택 | 분류 탭 4개, 메뉴 카드, 아래(넓은 화면은 오른쪽)에 장바구니. 메뉴를 누르면 온도·크기·수량 팝업이 뜬다 |
| 주문 확인 | 메뉴·수량·금액 표. 수량 조절, 삭제, 매장/포장 변경 |
| 결제 방식 선택 | 카드 결제 / 간편결제 / 카운터 결제. 고르면 안내 그림과 진행 막대가 나온다 |
| 주문 완료 | 연습 주문번호, 드시는 곳, 수량, 결제 방식, 금액 |

### 원본 번들에 들어 있는 규칙

| 항목 | 값 |
|---|---|
| 메뉴 | 4분류(커피·음료·차·디저트) 20개. 가격은 2,800원 ~ 6,500원 |
| 품절 표시 | 플레인 베이글 1개 (품절 화면 연습용) |
| 온도 제한 | 콜드브루·스무디·레모네이드는 ICE 만, 에스프레소는 HOT 만 |
| 크기 | 기본 / 크게. 크게는 **+500원** |
| 수량 | 한 줄에 1 ~ **99** 개 |
| 같은 메뉴 | 메뉴·온도·크기가 같으면 한 줄로 합쳐 수량만 늘린다 |
| 주문번호 | 001 부터 1씩 올라가고 999 다음은 001 |
| 무입력 시간 | 메뉴·확인·결제 화면에서 **120초** 동안 손대지 않으면 "주문 시간이 지났습니다" 팝업 |
| 연장 팝업 | **15초** 안에 "시간 연장"을 누르지 않으면 처음으로 |
| 남은 시간 초기화 | 화면을 누르거나, 키를 치거나, 터치하거나, 스크롤하면 120초로 되돌아간다 |
| 결제 연출 | 결제 방식을 고르고 **3.5초** 뒤 완료 화면 |
| 완료 화면 | **20초** 뒤 자동으로 처음 화면 |

## 6. 디자인

### 색

| 용도 | 색 |
|---|---|
| 배경 | `#f5f5f7` (라이트그레이), 카드·패널 `#ffffff` |
| 글자 | 본문 `#1d1d1f`, 보조 `#434348`, 흐린 안내 `#63636a` |
| 다음 행동 버튼 | 파랑 `#0066cc` (누를 때·올릴 때 `#0053a6`) |
| HOT / ICE 선택 | HOT `#a94027`, ICE `#27628c` |

다음에 누를 버튼 하나만 파란색으로 두고, 나머지는 흰색·회색으로 둬서 어디를 눌러야 할지 바로 보이게 했다.

### 글자와 버튼 크기

- 주요 버튼 높이 **52 ~ 76px**, 메뉴·옵션·주요 문구 **19 ~ 30px**.
- 완료 화면의 주문번호는 **108px** (좁은 화면 86px).
- 한글 안내문은 `word-break: keep-all` 로 단어 중간에서 줄을 바꾸지 않는다.

### 글꼴

```css
font-family: -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Cafe Pretendard', system-ui, sans-serif;
```

- **애플 기기**: 시스템 글꼴(SF Pro, Apple SD Gothic Neo)을 쓴다.
- **윈도우·안드로이드**: 함께 넣은 Pretendard 를 쓴다. 그래서 애플 기기와 모양이 완전히 같지는 않다.
- Pretendard 는 가변 글꼴이라 500·550·650 같은 중간 굵기도 그대로 그려진다.
  `font-synthesis: none` 으로 브라우저가 가짜 굵게를 만들지 않게 했다.
- 애플 SF Pro 글꼴 파일은 라이선스상 배포할 수 없어 넣지 않았다.

### 화면 폭에 따른 배치

| 조건 | 바뀌는 것 |
|---|---|
| 폭 1024px 이상 | 메뉴 화면이 "메뉴 + 오른쪽 장바구니(360px)" 두 칸이 된다 |
| 폭 761 ~ 1023px | 메뉴 3열, 장바구니는 아래 250px 높이 |
| 폭 760px 이하 | 메뉴 2열, 시작 화면 선택지가 세로 한 줄, 글자를 한 단계 줄인다 |
| 폭 900px 이상 · 높이 1400px 이상 | 세로로 긴 키오스크용. 시작 제목·메뉴 글자를 키운다 |
| 높이 720px 이하 | 시작 화면 여백과 선택지 높이를 줄인다 |

### 움직임

- 화면 전환 0.24 ~ 0.28초, 팝업 0.18 ~ 0.24초로 짧게 둔다.
- 버튼을 누르면 살짝 작아지는 반응(`scale(.985)`)이 있다.
- 운영체제나 브라우저에서 **"동작 줄이기"** 를 켜면 모든 애니메이션이 꺼진다 (`prefers-reduced-motion`).

## 7. 접근성 보완 (`ui-enhancements.js`)

| 기능 | 내용 |
|---|---|
| 진행 단계 표시 | 시작 화면을 지나면 위쪽에 "1 메뉴 선택 · 2 주문 확인 · 3 결제 방식 · 4 주문 완료" 가 뜨고 지금 단계를 파랗게 칠한다 (`aria-current="step"`) |
| 단계별 안내 문구 | 단계마다 한 줄 안내를 보여 준다 |
| 탭 제목 | 브라우저 탭 제목을 "메뉴 선택 · 카페 주문 연습" 처럼 바꾼다 |
| 화면 제목 포커스 | 화면이 바뀌면 제목으로 포커스를 옮겨 화면 읽기 프로그램이 새 화면을 읽게 한다 |
| 금액 변화 알림 | 장바구니 총액이 바뀌면 "담은 메뉴의 총 금액은 ○원입니다" 를 화면 읽기 프로그램에 알린다 (`aria-live`) |
| 팝업 키보드 | 팝업이 뜨면 Tab 이 팝업 안에서만 돈다. Esc 는 옵션·결제 팝업을 취소한다. 닫히면 원래 버튼으로 포커스를 돌려준다 |
| 문구 교체 | "주문 확인하기", "주문 연습을 마쳤어요", "연습 주문번호" 처럼 연습용임이 드러나게 바꾼다 |

## 8. 검수 기록

`제작-확인.txt` 에 원문이 있다. 요약:

- 환경: 윈도우 Chrome 실제 브라우저.
- 화면 폭 360 · 390 · 600 · 768 · 900 · 1024 · 1366px 와 시작·메뉴·옵션·주문 확인·결제·완료 화면을 조합해 봤다.
- 확인 항목: 수량 변경 시 금액 계산, 결제 후 금액 일치, JavaScript 오류, 가로 넘침, 팝업 키보드 포커스, Esc 취소, 동작 줄이기, 로컬 글꼴 로드, 원본 번들이 바뀌지 않았는지.
- **남은 것**: 실제 교육용 터치 장비에서 화면 배율과 터치 반응을 확인해야 한다.

## 9. 한계와 고칠 때 주의할 점

- **원본 React/TypeScript 소스가 없다.** 메뉴·가격·타이머를 바꾸려면 원본 프로젝트가 필요하다.
  축약된 번들을 손으로 고치지 말 것.
- **디자인은 `clean-ui.css` 에서만 고친다.** 원본 번들이 만드는 클래스 이름에 맞춰 덮어쓰는 구조라,
  원본을 다시 빌드해 클래스 이름이 바뀌면 이 파일도 같이 맞춰야 한다.
- **`ui-enhancements.js` 는 화면 문구와 클래스 이름에 기대고 있다.** 원본의 버튼 문구나 구조가 바뀌면
  진행 단계 표시와 문구 교체가 조용히 멈출 수 있다. 원본을 바꾼 뒤에는 다섯 화면을 한 번씩 눌러 본다.
- 원본을 다시 빌드하면 번들 파일 이름의 해시가 바뀐다. `index.html` 의 `<script>`·`<link>` 경로도 같이 고친다.
- `index.html` 을 파일로 직접 열면 개발자 도구에 글꼴 **미리 불러오기** 실패가 한 줄 찍힌다.
  `file://` 에서는 `crossorigin` 미리 불러오기가 막히기 때문이다. 글꼴 자체는 `clean-ui.css` 의
  `@font-face` 로 정상 적용되고, 웹 서버로 열면 이 메시지도 없다 (2026-11-05 Chromium 으로 확인).
